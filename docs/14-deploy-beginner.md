# Гайд для полного новичка: от нуля до игры в Google Play

Инструкция рассчитана на человека, который **никогда не публиковал приложения** и, возможно,
никогда не работал с терминалом. Всё расписано так: «открой вот этот адрес → нажми вот здесь →
вставь вот это». Расширенные объяснения — в `DEPLOY.md` и `docs/01`–`13`, но для деплоя
достаточно этой страницы.

> Названия кнопок в интерфейсах Яндекс РСЯ и Google Play Console периодически меняются
> (это нормально), поэтому если видите похожую по смыслу надпись — нажимайте её. Логика шагов
> остаётся неизменной.

## 1. Мини-словарь (чтобы не пугали слова)

| Слово | Что это человеческим языком |
| --- | --- |
| **Репозиторий** | Папка с проектом на GitHub. У нас — `kirillpetrov08/yandex` |
| **Ветка (branch)** | Параллельная копия проекта. `main` — основная, `arena/9aea8e67-yandex` — где лежит готовая работа |
| **Pull Request (PR)** | Предложение «влить» изменения из одной ветки в другую. У нас открыт PR №1 |
| **Merge** | Кнопка, которая вливает изменения. После неё код из PR появляется в `main` |
| **Commit** | «Сохранить версию» — фиксация изменений с комментарием |
| **Actions** | Бесплатные компьютеры GitHub: по команде собирают ваше приложение в облаке |
| **AAB** | Файл приложения для загрузки в Google Play (`.aab`). Именно его грузят в Play |
| **APK** | Файл приложения для установки на телефон вручную (`.apk`) |
| **Keystore (`.jks`)** | «Цифровая печать» разработчика. Ей подписывается приложение. Потеряете — не сможете обновлять приложение в Play |
| **РСЯ** | Рекламная сеть Яндекса. Показывает рекламу в вашем приложении и платит за это |
| **Рекламный блок (ad unit)** | Конкретное «место» рекламы в приложении. У каждого блока свой ID вида `R-M-1234567-1` |
| **Плейсмент** | Где именно в игре показывается блок (меню, после партии, за награду) |
| **Play Console** | Личный кабинет разработчика Google Play, где вы публикуете приложение |
| **Трек (track)** | Канал раздачи версий: `Internal` (вы и пара друзей) → `Closed` (12 тестировщиков) → `Production` (все) |
| **Data safety** | Обязательная форма в Play: какие данные собирает приложение |
| **app-ads.txt** | Текстовый файл на вашем сайте, который подтверждает РСЯ, что сайт ваш. Без него часть рекламы не покупается |
| **Политика конфиденциальности** | Страница на сайте с описанием, какие данные собираются. Без неё Play не примет приложение |

## 4. Шаг 2 — вписать свои данные в 3 файла (15 минут)

Правки делаются **прямо в браузере**, ничего скачивать не нужно.

Общий порядок для любого файла:

1. Открыть файл в GitHub (адрес будет указан ниже).
2. Нажать значок **карандаша** справа сверху от содержимого файла («Edit this file»).
3. Внести правки в открывшемся окне редактора.
4. Нажать зелёную кнопку **Commit changes…** справа сверху.
5. В окне подтверждения оставить выбор **Commit directly to the `main` branch** и нажать
   **Commit changes**.

### 4.1 Файл `gradle.properties`

Адрес: https://github.com/kirillpetrov08/yandex/blob/main/gradle.properties

| Что найти (строка) | Что поменять | Пример |
| --- | --- | --- |
| `app.applicationId=com.blockpuzzle.app` | Идентификатор приложения. **Меняется только сейчас и больше никогда** | `app.applicationId=com.вашафамилия.blocks` — если смените, придётся поменять и `namespace` в `app/build.gradle.kts`, поэтому проще оставить как есть |
| `app.versionCode=1` | Номер версии для Play (целое число) | `1` для первого релиза, потом `2`, `3`… |
| `app.versionName=1.0.0` | Версия для людей | `1.0.0` |
| `ads.testMode=true` | Пока оставить `true` — это тестовые баннеры | На `false` поменяете в шаге 8, когда получите ID из РСЯ |
| `ads.bannerUnitId=…` и ещё 4 строки | Тоже оставить как есть — временно это демо-блоки Яндекса | Замените в шаге 8 |

Если ничего не менять — приложение всё равно соберётся и опубликуется, просто имя пакета будет
`com.blockpuzzle.app`. Это нормальный вариант.

### 4.2 Файл `app/src/main/java/com/blockpuzzle/app/Config.kt`

Адрес: https://github.com/kirillpetrov08/yandex/blob/main/app/src/main/java/com/blockpuzzle/app/Config.kt

Внутри — три строки:

- `SUPPORT_EMAIL` — впишите свою рабочую почту. **Её увидят пользователи**, поэтому не странную.

> Уже после публикации приложения править эти строки безопасно — они не влияют на версии.

## 5. Шаг 3 — ключ подписи (15 минут)

**Что это.** Play принимает только приложения, подписанные вашим личным ключом. Ключ — это файл
`upload-keystore.jks` плюс два пароля. **Если потерять ключ — обновления выпустить нельзя**
(придётся просить поддержку Google о «сбросе ключа»).

### Вариант A: создать ключ командой (без Android Studio)

1. Установите **JDK 17**: https://adoptium.net/temurin/releases/?version=17 → выберите свою систему,
   скачайте и установите (для Windows — `.msi`, просто «Next → Next → Finish»).
2. Создайте пустую папку для проекта, например `C:\blocks` (Windows) или `~/blocks` (macOS/Linux).
3. Откройте терминал:
   - **Windows:** нажмите `Win`, наберите `cmd`, откройте «Командная строка».
   - **macOS:** `Cmd+Space`, наберите «Терминал».
   - **Linux:** `Ctrl+Alt+T`.
4. Перейдите в созданную папку:
   - Windows: `cd C:\blocks`
   - macOS/Linux: `cd ~/blocks`
5. Вставьте команду (можно скопировать целиком, она задаст несколько вопросов):

```bash
keytool -genkeypair -v -keystore upload-keystore.jks -alias upload -keyalg RSA -keysize 4096 -validity 10000
```

Ответы на вопросы:

| Вопрос | Что ввести |
| --- | --- |
| `Enter keystore password:` | Придумайте пароль (≥ 6 символов). Запишите! |
| `Re-enter new password:` | Повторите его |
| `What is your first and last name?` | Ваше имя, например `Kirill Petrov` |
| `What is the name of your organizational unit?` | Можно `Self` или оставить пустым (Enter) |
| `What is the name of your organization?` | `Self` или название, если есть |
| `What is the name of your City or Locality?` | Город, например `Helsinki` |
| `What is the name of your State or Province?` | Регион/область |
| `What is the two-letter country code for this unit?` | `FI`, `RU` и т.п. |
| `Is CN=… correct?` | `yes` (или `y`) |
| `Enter key password for <upload>` | **Нажмите просто Enter** — тогда пароль ключа = пароль хранилища (так проще не запутаться) |

В папке появится файл `upload-keystore.jks`.

6. Проверьте, что ключ создан: `keytool -list -v -keystore upload-keystore.jks`
   (введите пароль — увидите `Alias name: upload` и отпечаток).

> Если Windows пишет «keytool не является внутренней командой» — закройте окно терминала, откройте
> заново (установщик обновил переменные пути). Если всё равно не находит — выполните команду полным
> путём, например: `"C:\Program Files\Eclipse Adoptium\jdk-17\bin\keytool.exe" -genkeypair -v -keystore upload-keystore.jks -alias upload -keyalg RSA -keysize 4096 -validity 10000`

### Вариант B: создать ключ через Android Studio

1. Установите Android Studio (https://developer.android.com/studio) и откройте в нём проект
   (File → Open → папка с проектом).
2. Меню **Build → Generate Signed Bundle / APK…**.
3. Выберите **Android App Bundle** → **Next**.
4. В строке «Key store path» нажмите **Create new…**.
5. Заполните: путь к файлу (`upload-keystore.jks`), пароль хранилища, alias `upload`, пароль ключа,
   ниже — имя, организацию, город, регион, страну. Нажмите **OK** (файл ключа создан).
6. Мастер можно закрыть (Cancel) — дальше AAB соберём в облаке.

### Запишите и сохраните (прямо сейчас!)

| Что | Ваше значение |
| --- | --- |
| Файл ключа | `upload-keystore.jks` |
| Пароль хранилища (store password) | ________________ |
| Алиас | `upload` |
| Пароль ключа (key password) | ________________ (если не задавали — тот же, что пароль хранилища) |

Скопируйте файл ключа и эти пароли **в два независимых места**: менеджер паролей (Bitwarden,
1Password, Google Password Manager) и зашифрованный архив в облаке. Это самая частая потеря у
разработчиков-одиночек, и она делает невозможным выпуск обновлений.

## 6. Шаг 4 — секреты в GitHub (10 минут)

Секреты — это «сейф» GitHub, из которого облачная сборка берёт пароли, не показывая их в коде.

1. Откройте https://github.com/kirillpetrov08/yandex
2. Нажмите **Settings** (вкладка сверху, самая правая).
3. В левом меню: **Secrets and variables → Actions**.
4. Нажмите зелёную кнопку **New repository secret**.
5. Заполните поля **Name** и **Secret**, нажмите **Add secret**. Повторите для всех четырёх строк:

| Name (вводить точно так) | Secret (что вставлять) |
| --- | --- |
| `KEYSTORE_PASSWORD` | Пароль хранилища из шага 3 |
| `KEY_ALIAS` | `upload` |
| `KEY_PASSWORD` | Пароль ключа из шага 3 |
| `KEYSTORE_BASE64` | Содержимое файла `upload-keystore.jks`, закодированное в base64 — см. ниже |

### Как получить значение для `KEYSTORE_BASE64`

Выполните в том же терминале, где лежит `upload-keystore.jks`:

- **Windows (PowerShell):** откройте PowerShell в папке с ключом (Shift + правый клик по папке →
  «Открыть окно PowerShell здесь»), затем:
  ```powershell
  [Convert]::ToBase64String([IO.File]::ReadAllBytes("upload-keystore.jks")) | Set-Clipboard
  ```
  Строка окажется в буфере обмена — просто вставьте её в поле Secret.
  (Если PowerShell ругается на Set-Clipboard: `... | Out-File -Encoding ascii keystore.txt` и
  откройте файл `keystore.txt` Блокнотом — там будет одна длинная строка.)
- **macOS:**
  ```bash
  base64 -i upload-keystore.jks | pbcopy
  ```
- **Linux:**
  ```bash
  base64 -w0 upload-keystore.jks | xclip -selection clipboard   # или просто на экран:
  base64 -w0 upload-keystore.jks
  ```

Получится одна очень длинная строка из букв и цифр (десятки тысяч символов). GitHub её принимает
спокойно — окно просто «съест» вставку целиком.

## 7. Шаг 5 — включить и запустить сборку в облаке (15 минут)

GitHub не разрешает мне (агенту) загружать файлы в папку `.github/workflows`, поэтому этот файл
нужно создать самому — это одна вставка.

### 7.1 Создать файл конфигурации сборки

1. Откройте https://github.com/kirillpetrov08/yandex
2. Нажмите кнопку **Add file** → **Create new file**.
3. В поле имени файла введите ровно это (слэши сами создадут папки):
   ```
   .github/workflows/android.yml
   ```
4. Откройте в новой вкладке файл с готовым содержимым:
   https://github.com/kirillpetrov08/yandex/blob/main/docs/ci/android.yml
5. Справа сверху от содержимого нажмите иконку **Copy raw file** (копирует текст целиком).
6. Вернитесь в новую вкладку с создаваемым файлом, кликните в большое текстовое поле и вставьте
   содержимое (`Ctrl+V` / `Cmd+V`).
7. Нажмите **Commit changes…** → **Commit changes**.

### 7.2 Запустить сборку

1. В репозитории нажмите вкладку **Actions**.
2. Слева выберите **Android CI**.
3. Справа нажмите кнопку **Run workflow** → появится выпадающее окошко → снова **Run workflow**.
4. Через 5 секунд обновите страницу: появится запуск с жёлтым кружком (собирается). Полная сборка
   занимает **5–10 минут**, после чего кружок станет зелёной галочкой.
5. Нажмите на строку запуска → прокрутите вниз до блока **Artifacts** → нажмите
   **build-outputs** — скачается zip-архив.
6. Распакуйте архив. Внутри:
   - `bundle/release/app-release.aab` — **это и грузится в Google Play**;
   - `apk/debug/app-debug.apk` — для проверки на телефоне.

### 7.3 Если сборка упала (красный крестик)

1. Откройте упавший запуск, разверните красный шаг — там будет текст ошибки.
2. Проверьте самый частый случай: в шаге **Release AAB** или **Проверка подписи AAB** стоит жёлтое
   предупреждение «Нет ключа подписи» — значит, секреты из шага 4 не заданы (или заданы с опечаткой
   в имени, например `KEY_STORE_PASSWORD` вместо `KEYSTORE_PASSWORD`).
3. Если ошибка в шаге **Unit-тесты** — пришлите мне текст ошибки, это код, разберусь.

### 7.4 Альтернатива: собрать локально (если хотите без облака)

Если установлена Android Studio:

1. File → Open → папка проекта.
2. Внизу откройте вкладку **Terminal** и выполните:
   ```
   ./gradlew bundleRelease
   ```
   (Windows: `gradlew.bat bundleRelease`)
3. Готовый файл появится в `app/build/outputs/bundle/release/app-release.aab`.
   Чтобы он был подписан вашим ключом, в корне проекта должен лежать файл `keystore.properties`:
   ```
   storeFile=upload-keystore.jks
   storePassword=ПАРОЛЬ
   keyAlias=upload
   keyPassword=ПАРОЛЬ
   ```
   и сам `upload-keystore.jks` рядом с ним.

## 8. Шаг 6 — проверить игру на телефоне (20 минут)

Пока реклама тестовая (`ads.testMode=true`), вы увидите демонстрационные объявления Яндекса — это
правильное поведение, дохода от них нет.

1. Возьмите `app-debug.apk` из скачанного архива (шаг 5.2).
2. Перенесите файл на телефон: по кабелю, через Telegram «Избранное» (отправьте себе файл) или
   Google Drive.
3. На телефоне откройте файл. Android спросит разрешение **«Устанавливать неизвестные приложения»** —
   разрешите только для того приложения, через которое открываете (Файлы/Telegram) и повторите.
4. Запустите игру и проверьте по списку:
   - [ ] экран согласия появляется при первом запуске, кнопка «Принять все» работает;
   - [ ] играется: перетаскиваются фигуры, ряды исчезают, очки растут;
   - [ ] в меню внизу виден баннер (тестовый);
   - [ ] после проигрыша есть кнопки «Продолжить» и «Удвоить монеты» со словом «Смотреть рекламу»;
   - [ ] кнопка «Магазин» открывается, темы покупаются за монеты;
   - [ ] реклама **не появляется во время партии**;
   - [ ] после закрытия приложения и повторного запуска рекорд и монеты сохранились.
5. Если что-то не так — сфотографируйте экран и напишите мне, поправлю код и пересоберём.

## 9. Шаг 7 — сайт: политика конфиденциальности и `app-ads.txt` (15 минут)

**Зачем.** Google Play требует публичную политику конфиденциальности. А `app-ads.txt` нужен, чтобы
РСЯ могла подтвердить, что приложение ваше: без него часть рекламных систем не покупает показы,
и доход падает.

**Почему отдельный репозиторий.** Файл `app-ads.txt` должен лежать в **корне домена**. Если
публиковать сайт из этого проекта, адрес получится `.../yandex/...` — это подпапка, и РСЯ файл не
найдёт. Поэтому делаем «сайт пользователя»: репозиторий с именем `kirillpetrov08.github.io` — у него
адреса короткие: `https://kirillpetrov08.github.io/...`.

1. Откройте https://github.com/new
2. **Repository name**: `kirillpetrov08.github.io` (именно так, точка в имени обязательна).
3. Выберите **Public** (для сайта пользователя нужен публичный репозиторий — там только два
   публичных файла, кода игры в нём не будет).
4. Нажмите **Create repository**.
5. На появившейся странице нажмите ссылку **uploading an existing file**.
6. Перетащите в окно два файла из проекта:
   - `privacy-policy.html` (лежит в корне репозитория `yandex`);
   - `app-ads.txt` (тоже в корне `yandex`).
7. Внизу нажмите **Commit changes**.
8. Через 1–2 минуты проверьте в браузере (откроется — значит всё работает):
   - https://kirillpetrov08.github.io/privacy-policy.html
   - https://kirillpetrov08.github.io/app-ads.txt

> `app-ads.txt` пока содержит заглушку `YOUR_PARTNER_ID` — настоящий ID впишете в шаге 8.5 и тогда
> обновите файл: в репозитории `kirillpetrov08.github.io` откройте `app-ads.txt` → карандаш →
> правка → Commit changes.

## 10. Шаг 8 — РСЯ: приложение, блоки, app-ads.txt (40 минут)

### 10.1 Регистрация и оферта (10 минут)

1. Откройте https://partner.yandex.ru — войдите аккаунтом Яндекса (или создайте).
2. Заполните профиль партнёра: тип (физлицо/самозанятый/ИП/ООО), контакты.
3. Примите **оферту** — без неё показы со временем приостанавливаются.
4. Заполните **платёжные данные** (раздел «Документы и выплаты» / «Платёжные данные»):
   для физлица — ФИО, ИНН, паспортные данные, реквизиты счёта. Пока сумма небольшая, реклама
   работает и так, но **после превышения порога 10 000 ₽** показы останавливаются до заполнения —
   сделайте это сразу.

### 10.2 Добавить приложение

1. В левом меню: **Реклама в приложениях → Приложения**.
2. Нажмите **Добавить приложение**.
3. Заполните:

| Поле | Что вписать |
| --- | --- |
| Платформа | Android |
| Название | `Блоки — головоломка` (или как в Play) |
| Идентификатор (package name) | `com.blockpuzzle.app` — **ровно как в `gradle.properties`** |
| Ссылка на магазин | пока пусто; добавите после публикации в Play |
| Сайт разработчика | `https://kirillpetrov08.github.io/privacy-policy.html` |

4. Сохраните и отправьте приложение **на модерацию** (кнопка «Отправить на модерацию»).
   Обычно занимает до 2 суток. До одобрения показы идут в тестовом режиме (без дохода).

### 10.3 Создать 5 рекламных блоков

Раздел **Реклама в приложениях → Блоки → Создать блок**. Для каждого блока: выбрать формат →
выбрать приложение `Блоки — головоломка` → вписать название → сохранить → **скопировать ID**
(кнопка копирования рядом с ID, выглядит как `R-M-1234567-1`).

| Формат блока | Название блока (советую так) | Зачем он в игре |
| --- | --- | --- |
| Баннер (адаптивный) | `bp_banner_menu` | внизу меню, магазина, статистики |
| Межстраничная реклама | `bp_interstitial_gameover` | между партиями, не чаще 1 раза в минуту |
| Реклама с вознаграждением | `bp_rewarded_continue` | «Продолжить», «×2 монеты», монеты в магазине |
| Реклама при открытии приложения | `bp_appopen_launch` | запуск и возврат в игру |
| Нативная реклама | `bp_native_shop` | внутри магазина |

Важные настройки при создании:

- **Баннер:** оставьте автообновление включённым (по умолчанию 60 секунд). В игре уже есть
  корректное поведение — свой таймер не добавляйте.
- **Реклама с вознаграждением:** укажите **название валюты** и **сумму вознаграждения** за просмотр
  (например, «монеты» и `50`) — это нужно сети для статистики. Награду выдаёт код игры: он уже
  выдаёт 50 монет.
- **География:** на старте оставьте как есть («Максимальный доход»), порог eCPM не задавайте.

### 10.4 Вписать ID блоков в проект

Вернитесь к файлу `gradle.properties` в репозитории `yandex` (карандаш → правка → Commit changes):

```properties
ads.testMode=false
ads.bannerUnitId=R-M-XXXXXXX-1
ads.interstitialUnitId=R-M-XXXXXXX-2
ads.rewardedUnitId=R-M-XXXXXXX-3
ads.appOpenUnitId=R-M-XXXXXXX-4
ads.nativeUnitId=R-M-XXXXXXX-5
```

Вместо `R-M-XXXXXXX-1` … вставьте свои пять ID из РСЯ. Строку `ads.testMode=true` поменяйте на
`false` — иначе в релизе останутся тестовые объявления и дохода не будет.

После этого **пересоберите AAB** (шаг 5.2): Actions → Android CI → Run workflow. Новый архив с
`app-release.aab` понадобится для загрузки в Play.

### 10.5 app-ads.txt: вписать свой ID партнёра

1. В РСЯ откройте **Настройки → Общие** → блок **app-ads.txt** (может называться «Инструкция по
   app-ads.txt», там же кнопка скачивания готового фрагмента).
2. Скопируйте оттуда строку с вашим ID партнёра — выглядит так:
   `kirillpetrov08.github.io, 1234567, DIRECT` (номер — это и есть ID партнёра).
3. Откройте https://github.com/kirillpetrov08/kirillpetrov08.github.io/blob/main/app-ads.txt →
   карандаш → замените строку с `YOUR_PARTNER_ID` на свою → **Commit changes**.
4. В РСЯ нажмите **Отправить на проверку** (проверка — раз в сутки). Статус должен стать
   «файл найден, ошибок нет».

> Если РСЯ пишет «Нет данных о файле» — откройте `https://kirillpetrov08.github.io/app-ads.txt`
> в браузере: если файл не открывается, значит не настроен сайт (шаг 7) или прошло мало времени.

## 11. Шаг 9 — аккаунт и приложение в Google Play (1–2 часа)

### 11.1 Создать аккаунт разработчика (делайте заранее — верификация может занять дни)

1. Откройте https://play.google.com/console
2. Нажмите **Get started** и войдите аккаунтом Google (лучше отдельным, не личным).
3. Выберите тип аккаунта **Personal** (для организаций потребуется номер D-U-N-S — новичку не нужно).
4. Заполните данные разработчика: имя (будет видно в Play), адрес, телефон, e-mail. Телефон
   придётся подтвердить кодом.
5. Оплатите $25 картой (разово, навсегда).
6. Пройдите **верификацию личности**: загрузите фото документа (паспорт/ID) и селфи. Занимает от
   нескольких часов до пары суток. Без этого доступ к публикации не откроется.

### 11.2 Создать приложение

1. В Play Console слева: **All apps → Create app**.
2. **App name** — как показывать в магазине: `Блоки — головоломка 8×8`.
   Рядом **Default language**: `Русский — ru-RU`. (Позже добавите английскую локализацию.)
3. **App or game** → `Game`. **Free or paid** → `Free`.
4. Прочитайте и отметьте две декларации (Developer Program Policies, US export laws) → **Create app**.

### 11.3 Заполнить «App content» (обязательные формы)

В меню слева **Policy → App content**. Каждый раздел: нажать **Start / Manage** → заполнить →
**Save**. Ниже — что выбирать (расшифровки — в `store-listing/app-content.md`).

| Раздел | Что вводить |
| --- | --- |
| **Privacy policy** | ссылка `https://kirillpetrov08.github.io/privacy-policy.html` |
| **App access** | «All functionality is available without special access» (логина в игре нет) |
| **Ads** | «Yes, my app contains ads» |
| **Content rating** | Start → ввести e-mail → заполнить анкету **IARC**: на все вопросы про насилие, наркотики, азартные игры и т.п. — `No`; `Contains ads` → **Yes**. Получите рейтинг вида `3+` / `Everyone` |

**Data safety** (заполняется за 3–4 минуты, точные ответы — в `store-listing/data-safety.md`):

- «Does your app collect or share any of the required user data types?» → **Yes**
- «Is all user data encrypted in transit?» → **Yes**

- В разделе про рекламный идентификатор: «Does your app use advertising ID?» → **Yes**,
  Purpose → `Advertising or marketing`.

| Phone screenshots | перетащите 4 файла `store-listing/screenshots/phone-ru-*.png` (можно и 8, добавив `phone-en-*`) |

Нажмите **Save**. Для английского языка: слева **Manage translations → Add your own translation →
English (US)** и вставьте текст из `store-listing/en.md` (имя, описания), скриншоты можно оставить те же.

Затем **Store settings** (там же в левом меню): Category → `Games → Puzzle`; Contact details →

Save.

### 11.5 Загрузить AAB в закрытый тест (Internal testing)

1. Меню слева: **Test and release → Testing → Internal testing**.
2. Нажмите **Create new release**.
3. Если попросит, согласитесь на **Play App Signing** (оставьте значения по умолчанию — Google
   будет хранить «печать» релиза у себя, а ваш `upload-keystore.jks` останется ключом загрузки).
4. В разделе **App bundles** нажмите **Upload** и выберите файл `app-release.aab` из шага 10.4.
5. Дождитесь окончания обработки. Если Play покажет предупреждения — не страшно, главное чтобы не
   было красных ошибок (самая частая: «апп подписан неправильным ключом» — значит собрали AAB без
   вашего ключа).
6. Поле **Release notes** — вставьте текст из `store-listing/release-notes.md`.
7. **Save** → **Review release** → **Start rollout to Internal testing** → **Continue**.
8. Вкладка **Testers**: создайте список — **Create email list**, впишите свои и друзей e-mail →
   Save; затем включите его в трек. Скопируйте появившуюся **ссылку для тестировщиков**
   (вида `https://play.google.com/apps/internaltest/…`) и откройте её на своём телефоне:
   Play предложит установить приложение. Проверьте, что **реальная реклама** показывается,
   и что она не перекрывает игровое поле.

### 11.6 Закрытый тест: 12 тестировщиков, 14 дней (для новых личных аккаунтов)

Google требует перед продакшеном: **минимум 12 человек**, которые установили приложение из закрытого
теста, и **14 дней непрерывного теста**.

1. Меню: **Testing → Closed testing → Create track**.
2. Загрузите тот же AAB (**Create new release** → Upload), добавьте **список тестировщиков**
   (12+ реальных e-mail — друзья, знакомые, коллеги, сообщества).
3. **Start rollout**.
4. Разошлите им ссылку теста (та же механика, что в Internal) и попросите установить и запустить
   игру хотя бы раз.
5. Оставляйте тест включённым **14 дней подряд** (таймер Google считает непрерывное участие).
6. Через 14 дней в **Dashboard** появится кнопка **Apply for production access** — подайте заявку,
   честно ответив на вопросы (сколько тестировщиков, какие отзывы получили, что исправили).
   Ответ приходит обычно за 1–7 дней.

> Пока идёт тест, полезно: собрать замечания, поправить тексты, посмотреть в Play Console
> `Android vitals` (падения) и статистику запросов в РСЯ.

### 11.7 Продакшен-релиз

1. Меню: **Test and release → Production → Create new release**.
2. Загрузите `app-release.aab` (тот же или новый — с бо́льшим `app.versionCode`).
3. **Countries/regions** → выберите страны (проще «All countries»).
4. **Release notes** — вставьте текст.
5. **Save → Review release → Start rollout to Production**.
6. Модерация первого релиза в Play обычно занимает от нескольких часов до 3 дней. После публикации
   приложение появится в поиске Play по ссылке
   `https://play.google.com/store/apps/details?id=com.blockpuzzle.app`.

### 11.8 Вернуть ссылку в РСЯ

После публикации в Play вернитесь в РСЯ → **Приложения → ваше приложение → Просмотр** и добавьте
ссылку на страницу в Google Play. Это ускоряет проверку `app-ads.txt` и повышает доверие к площадке.

## 13. Если что-то пошло не так

| Симптом | Что это значит | Что делать |
| --- | --- | --- |
| Actions: красный крестик в шаге Release AAB | Нет секретов с ключом | Вернуться к шагу 4, проверить имена секретов |
| Actions: «AAB подписан debug-ключом» | То же самое | То же: без ключа Play сборку не примет |
| Play: «You uploaded an APK or Android App Bundle that was signed in debug mode» | Собрали без `keystore.properties`/секретов | Задать ключ и собрать заново |
| Play: «Version code 1 has already been used» | Номер версии не увеличили | Поднять `app.versionCode` в `gradle.properties` и пересобрать |
| Play: не активна кнопка публикации | Не заполнены формы App content | Пройти все пункты раздела App content (шаг 11.3) |
| Play: «Нужно 12 тестировщиков» | Новый личный аккаунт | Шаг 11.6 — закрытый тест 14 дней |
| РСЯ: «Файл app-ads.txt не найден» | Файла нет в корне домена | Проверить ссылку в браузере; сайт — репозиторий `kirillpetrov08.github.io` (шаг 7) |
| РСЯ: «Файл устарел» | Не хватает строк партнёра | Скопировать свежий фрагмент из РСЯ и обновить файл (шаг 10.5) |
| РСЯ: показы не идут | Приложение на модерации или не заполнены платёжные данные | Проверить статус приложения и раздел выплат (шаг 10.1) |
| В игре показываются тестовые баннеры «demo» | `ads.testMode=true` | Вписать реальные ID и `false` (шаг 10.4), пересобрать |
| Реклама не показывается вообще | Смотрим лог | Подключить телефон по USB и выполнить `adb logcat -v brief '*:S YandexAds'`; разбор — `docs/13-troubleshooting.md` |
| Игра крашится | Ошибка в коде/устройстве | Прислать мне текст ошибки (или скриншот) — поправлю |
