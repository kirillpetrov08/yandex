# Нативная реклама, рекламная лента и InStream

## Нативная реклама

Реклама, которая выглядит как обычный контент приложения: вы сами задаёте набор элементов и дизайн.
В блоке показываются комбинаторные объявления. Доступна и в РСЯ, и через Adfox.

Два способа оформления:

- **по шаблону** — внешний вид определяет SDK (быстро, но не в стиле вашего приложения);
- **вручную** — вы размечаете элементы и передаёте их в `NativeAdViewBinder`.

Дополнительно на Android можно показывать **слайдер** — набор объявлений, сменяющих друг друга при пролистывании.

### Интеграция (вручную)

```kotlin
val loader = NativeAdLoader(context)
val options = NativeAdOptions.Builder()
    .setShouldLoadImagesAutomatically(true)
    .build()

loader.loadAd(
    AdRequest.Builder(adUnitId).build(),
    options,
    object : NativeAdLoadListener {
        override fun onAdLoaded(nativeAd: NativeAd) {
            val binder = NativeAdViewBinder.Builder(nativeAdView) // корень — NativeAdView
                .setAgeView(age)                 // возрастная метка
                .setSponsoredView(sponsored)     // метка «реклама»
                .setFeedbackView(feedback)       // кнопка обратной связи/закрытия
                .setTitleView(title)
                .setBodyView(body)
                .setDomainView(domain)
                .setIconView(icon)
                .setMediaView(media)             // com.yandex.mobile.ads.nativeads.MediaView
                .setCallToActionView(callToAction)
                .build()

            when (nativeAd.bindNativeAd(binder)) {
                is AdBindingResult.Success -> nativeAdView.isVisible = true
                is AdBindingResult.Failure -> nativeAdView.isVisible = false  // прячем блок целиком
            }
        }

        override fun onAdFailedToLoad(error: AdRequestError) { /* backoff */ }
    },
)
```

Классы для разметки: контейнер `com.yandex.mobile.ads.nativeads.NativeAdView`,
медиа — `com.yandex.mobile.ads.nativeads.MediaView`.

### Правила размещения нативной рекламы (сокращённо и по делу)

Общие:

1. В блоке должны быть **все обязательные элементы**.
2. Блок **не должен быть полностью кликабельным** — кликабельны только элементы объявления.
3. Все элементы видны и различимы; фон не мешает читать текст, метки и предупреждения.
4. Нельзя менять ссылки элементов (сайт рекламодателя, быстрые ссылки).
5. На одном экране блок **не перезагружается чаще одного раза в 30 секунд**.
6. Переход по рекламе не должен быть единственным действием на экране.
7. Запрещены любые искусственные показы/клики/установки.

Обязательные элементы и ограничения:

| Элемент | Требование |
| --- | --- |
| Возрастная метка и указание, что это реклама | если обязательна по закону — SDK добавляет сама; менять текст и ссылку нельзя |
| Предупреждения | текст менять нельзя, предупреждения занимают **не менее 10% площади** объявления (ФЗ «О рекламе») |
| Заголовок | до **56 символов**, обязательно **кликабельный**, нельзя обрезать текст |
| Изображение | обязательно кликабельное, уменьшать можно, увеличивать нельзя |

### Как это сделано у нас

`ads/NativeAdSlot.kt` + разметка `res/layout/native_ad_card.xml`:

- инфлейтим блок из XML (проще поддерживать и без «магии» в коде);
- передаём в `NativeAdViewBinder` все обязательные вьюхи;
- при `AdBindingResult.Failure` блок полностью скрывается — «пустой» рекламный контейнер оставлять нельзя;
- держим паузу 30 секунд между загрузками;
- `cancelLoading()` и `setNativeAdEventListener(null)` при уходе с экрана.

## Рекламная лента (Feed)

Формат «бесконечной» ленты объявлений: подходит для экранов, где уже есть похожая механика
(лента новостей, видео, «другие игры»). Объявления грузятся порциями, десятками штук.
Логика такая же, как у нативной рекламы, но контейнер — RecyclerView/Compose-список,
а данные приходят как страницы объявлений.

Когда использовать: если у вас есть экран-лента. В нашей игре такое место одно — магазин,
и там выгоднее нативный блок + rewarded за монеты.

## InStream

Формат для монетизации **видеоконтента**: рекламные вставки внутри вашего видео (pre/mid/post-roll).
InStream-объявление состоит из сценария с несколькими видеоблоками; тип блока определяет,
как ролик проигрывается относительно основного видео.

Нужен, только если в приложении есть собственный плеер с видео (в игре — например, вступительный
ролик или раздел с гайдами). Требует отдельной работы с плеером (в примере Яндекса используется
ExoPlayer + `SampleInstreamAdPlayer`).

## Что выбирать в игре

1. **Rewarded** — база дохода.
2. **Interstitial** — с частотными ограничениями.
3. **Sticky banner** — на «спокойных» экранах.
4. **Native** — там, где нужен блок в дизайне (магазин, список уровней, экран результатов).
5. **App Open** — старт и возврат из фона.
6. **Feed/InStream** — только если в игре реально есть лента или видеоплеер.
