# Публикация в Google Play: пошагово

Ниже — всё, что остаётся сделать вам (код уже готов). Порядок проверенный: сначала аккаунт и
подпись, потом сборка AAB, потом Play Console, в конце — реклама РСЯ.

## Шаг 0. Что понадобится

- Google Play Developer аккаунт (единоразовый платёж $25, для физлиц доступен).
- JDK 17 и Android Studio (или собранный артефакт из GitHub Actions, см. [ci/android.yml](ci/android.yml)).
- Публичный сайт — для политики конфиденциальности и файла `app-ads.txt`
  (проще всего публичный репозиторий `<логин>.github.io`).
- Аккаунт РСЯ (partner.yandex.ru) — для реальных ID блоков.

## Шаг 1. Задайте свои идентификаторы

1. В `gradle.properties`:
   - `app.applicationId` — **выберите сразу и навсегда** (после публикации изменить нельзя);
   - `app.appNameRu` / `app.appNameEn` — название, оно попадёт в `strings.xml` (или отредактируйте
     `app/src/main/res/values*/strings.xml` напрямую);
   - `app.versionCode` / `app.versionName` — начните с 1 / 1.0.0.
2. В `app/src/main/java/com/blockpuzzle/app/Config.kt`:
   - `PRIVACY_POLICY_URL` — ваш адрес политики;
   - `PLAY_MARKET_URL` — ссылка на страницу приложения;
   - `SUPPORT_EMAIL` — рабочая почта (её увидят пользователи).

## Шаг 2. Ключ подписи (upload key)

Ключ нужен для загрузки AAB в Play. **Потеря ключа = невозможность обновлять приложение**
(спасает только запрос сброса через поддержку Google).

```bash
keytool -genkeypair -v \
  -keystore upload-keystore.jks \
  -alias upload \
  -keyalg RSA -keysize 4096 -validity 10000
```

Создайте в корне проекта файл `keystore.properties` (он уже в `.gitignore`, в репозиторий не попадёт):

```properties
storeFile=upload-keystore.jks
storePassword=ВАШ_ПАРОЛЬ
keyAlias=upload
keyPassword=ВАШ_ПАРОЛЬ
```

> **Сделайте резервную копию** `upload-keystore.jks` и паролей в двух независимых местах
> (например, менеджер паролей + зашифрованный архив в облаке). Это самая частая потеря
> у разработчиков-одиночек.

Если хотите собирать релиз в GitHub Actions, добавьте в репозиторий секреты
(Settings → Secrets and variables → Actions):

| Секрет | Значение |
| --- | --- |
| `KEYSTORE_BASE64` | файл `upload-keystore.jks`, закодированный в base64: `base64 -w0 upload-keystore.jks` |
| `KEYSTORE_PASSWORD` | пароль хранилища |
| `KEY_ALIAS` | `upload` |
| `KEY_PASSWORD` | пароль ключа |
| `PLAY_SERVICE_ACCOUNT_JSON` | необязательно: ключ сервисного аккаунта Google Play для автозагрузки AAB |

Workflow сам декодирует base64 в `upload-keystore.jks`, подставит путь в переменную
`KEYSTORE_FILE` (её читает `app/build.gradle.kts`), проверит подпись через `jarsigner`
и положит AAB в артефакты. Шаблон — `docs/ci/android.yml` (скопируйте его в
`.github/workflows/android.yml`, там же в комментариях описаны все секреты).

## Шаг 3. Сборка AAB

Локально (путь A — сборка в GitHub Actions — описан в [`DEPLOY.md`](../DEPLOY.md)):

```bash
./gradlew clean testDebugUnitTest      # тесты логики игры и рекламных политик
./gradlew bundleRelease                # это и заливается в Play
./gradlew assembleRelease              # APK — чтобы проверить на своём телефоне
```

Файлы:

- AAB: `app/build/outputs/bundle/release/app-release.aab`
- APK: `app/build/outputs/apk/release/app-release.apk`

Проверьте APK на реальном устройстве с **реальными** ad unit ID (см. Шаг 6) — до загрузки в Play.

## Шаг 4. Создание приложения в Play Console

1. **Create app**: название, язык по умолчанию, тип «Игра», «Бесплатное».
2. **App content** (обязательно пройти всё):
   - Privacy policy — ссылка;
   - Ads — «Да, приложение содержит рекламу»;
   - Content rating — заполните анкету (для нашей игры выйдет 3+/Everyone);
   - Target audience — 13+ (не «дети»), иначе применится Families Policy и придётся
     убрать рекламный идентификатор;
   - Data safety — см. таблицу ниже;
   - Government apps, Financial features, Health — «Нет».
   - **Advertising ID**: «Использует рекламный идентификатор» — да.
3. **Store listing** — тексты и графика (требования Play):

| Элемент | Требование |
| --- | --- |
| Иконка | 512×512 PNG, без прозрачности |
| Feature graphic | 1024×500 PNG/JPEG |
| Скриншоты телефона | 2–8 шт., минимум 320 px по короткой стороне |
| Короткое описание | до 80 символов |
| Полное описание | до 4000 символов, ключевые слова — естественно |
| Название | до 30 символов |

Ключевые слова для ASO (RU): `головоломка`, `блоки`, `кубики`, `пазл`, `2048`, `без интернета`,
`на логику`, `для взрослых`, `offline`. Не повторяйте одно слово более 3–4 раз.

4. **Release → Testing → Closed testing**: загрузите AAB, добавьте тестировщиков.

> Для новых **личных** аккаунтов разработчиков Google требует перед продакшеном провести
> закрытое тестирование не менее 12 тестировщиков в течение 14 дней подряд.
> Заранее найдите знакомых/сообщество, иначе релиз задержится на две недели.

## Шаг 5. Настройка Data safety (для нашего приложения)

| Категория | Ответ |
| --- | --- |
| Идентификаторы устройства / рекламный ID | Собирается, для рекламы и аналитики, не передаётся третьим лицам кроме рекламных партнёров |
| Действия в приложении | Не собирается (прогресс хранится локально) |
| Местоположение | Не собирается |
| Персональные данные (имя, email) | Не собирается |
| Шифрование при передаче | Да |
| Удаление данных по запросу | Да — почта поддержки |

Это соответствует тому, что делает SDK Яндекса: он использует рекламный идентификатор и
технические данные устройства, а игровой прогресс остаётся на устройстве.

## Шаг 6. Подключение реальной рекламы (РСЯ)

1. В интерфейсе РСЯ создайте блоки:
   - Баннер (адаптивный) — для меню/магазина;
   - Межстраничная реклама;
   - Реклама с вознаграждением (укажите валюту «монеты» и награду, например 50);
   - Реклама при открытии приложения;
   - Нативная реклама (для магазина).
2. Скопируйте ID вида `R-M-XXXXXXX-Y` в `gradle.properties`:

```properties
ads.testMode=false
ads.bannerUnitId=R-M-XXXXXXX-1
ads.interstitialUnitId=R-M-XXXXXXX-2
ads.rewardedUnitId=R-M-XXXXXXX-3
ads.appOpenUnitId=R-M-XXXXXXX-4
ads.nativeUnitId=R-M-XXXXXXX-5
```

3. Пересоберите релиз **с тем же versionCode+1** и загрузите обновление.
4. Убедитесь, что `versionCode` в Play больше предыдущего — иначе загрузка не пройдёт.

> Тестовые блоки в релизе = вы теряете доход и рискуете модерацией: убедитесь,
> что `ads.testMode=false` и ID реальные.

## Шаг 7. Сайт разработчика, app-ads.txt, политика

1. Возьмите файлы `privacy-policy.html` и `app-ads.txt` из корня этого репозитория.
2. Создайте **публичный** репозиторий с именем `<логин>.github.io` (у нас — `kirillpetrov08.github.io`):
   GitHub Pages для обычного репозитория на бесплатном плане работает только в публичных
   репозиториях, а сайт пользователя `<логин>.github.io` даёт короткие адреса в корне домена.
3. Положите оба файла в корень этого репозитория — сайт включится сам.
4. Проверьте в браузере:
   - `https://kirillpetrov08.github.io/privacy-policy.html`
   - `https://kirillpetrov08.github.io/app-ads.txt` (в нём вы уже заменили `YOUR_PARTNER_ID`)
5. Укажите сайт разработчика `https://kirillpetrov08.github.io/privacy-policy.html` в Play Console
   (Store settings → Developer website) — именно по этому домену РСЯ будет искать `app-ads.txt`.

> Почему не подпапка: РСЯ (как и спецификация IAB) ищет `app-ads.txt` в **корне домена**. У сайта
> проекта адрес выглядит как `<логин>.github.io/<репозиторий>/` — это не корень, поэтому файл
> нужно держать на сайте пользователя. Если хочется свой бренд — купите домен и положите файлы
> в его корень.

## Шаг 8. Продакшен-релиз и первые дни

1. Проверьте **Release → Production → Create new release**, загрузите AAB, добавьте release notes.
2. Staged rollout: начните с 10–20% пользователей (если аудитория есть), дальше — на 100%.
3. Первые 48 часов смотрите:
   - Crash-free rate, ANR (должно быть > 99.5% и < 0.5%);
   - показы рекламы в РСЯ (должны появиться в течение суток после модерации приложения);
   - D1 retention и средний балл отзывов.
4. Отвечайте на отзывы: это влияет и на рейтинг, и на установки.

## Шаг 9. Что дальше (вторая итерация)

- Подключить медиацию Яндекса (In-App Bidding) — самый быстрый способ поднять eCPM.
- Добавить AppMetrica: показы/DAU, воронку проигрыш → rewarded → новая партия.
- Добавить «Убрать рекламу» через Play Billing (при 1000+ DAU).
- Обновлять SDK и `targetSdk` раз в год (иначе Play перестанет принимать обновления).

## Частые причины отказа Play при первой загрузке

| Причина | Как избежать |
| --- | --- |
| Не заполнена форма Data safety | заполнить до отправки |
| Нет политики конфиденциальности | ссылка в App content + на сайте |
| targetSdk ниже 36 | в проекте уже 36, не переопределяйте |
| Реклама не декларирована | «Содержит рекламу» = Да |
| Тестирование не пройдено (новый личный аккаунт) | 12 тестировщиков, 14 дней |
| Иконка/графика не соответствует требованиям | 512×512 и 1024×500 |
| Описание обещает то, чего нет в игре | описывайте только реальные возможности |
