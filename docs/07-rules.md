# Все правила: размещение, модерация, приватность, Google Play

Это самый важный документ репозитория. Здесь собраны требования, нарушение которых
приводит к отказу в модерации, блокировке приложения или блокировке аккаунта,
и требования Google Play, которые нужно закрыть до публикации.

## 1. Правила участия в РСЯ и требования к приложениям

Официальные документы:

- **Правила участия в Рекламной сети Яндекса** — <https://yandex.ru/legal/partner/>
- **Оферта на оказание услуг** — <https://yandex.ru/legal/yan_service_offer/>
- **Требования к рекламе в мобильных приложениях** — приложения к оферте (см. ссылки в справке РСЯ)
- **Модерация приложений** — <https://ads.yandex.com/helpcenter/ru/payments/app-moderation>

### Что категорически нельзя

1. **Искусственные показы, клики, установки.** Любая автоматизация, эмуляторы кликов, «накрутка» —
   постоянная блокировка аккаунта без возможности восстановления.
2. **Стимулирование кликов**: «нажми на рекламу и получи монеты/жизнь», интерактивные подсказки,
   стрелки, указывающие на баннер.
3. **Размещение элементов приложения на рекламном блоке** или поверх креатива: свои кнопки, рамки,
   затемнения, счётчики, «закрыть» вместо креативной кнопки.
4. **Реклама вплотную к элементам игры**, из-за чего пользователь кликает случайно.
   Это самая частая причина отказа: «пользователь нажимает на рекламу, играя».
5. **Скачки контента при появлении баннера** (баннер вставляется и сдвигает кнопки) —
   напрямую упомянуто как причина отклонения и как источник случайных кликов.
6. **Своё оформление вокруг креатива**, изменяющий смысл: подписи, ссылки обратного отсчёта,
   «подарки», фейковые кнопки закрытия.
7. **Сокрытие рекламы**: реклама за пределами экрана, нулевые/подозрительные размеры, `alpha=0`,
   размещение под другими вью.
8. **Некорректный контент приложения**: пустое/некачественное приложение, отсутствие реального
   контента, приложение-обёртка (WebView без ценности), дубликаты.
9. **Нарушение законодательства о рекламе**: сокрытие возрастной метки/предупреждений,
   изменение переданных Яндексом текстов и ссылок.

### Что обязательно

1. Реклама видна, кнопка закрытия у полноэкранных форматов доступна.
2. Все обязательные элементы нативной рекламы на месте (см. [06](06-native-feed-instream.md)).
3. Реклама не перекрывает контент и элементы управления.
4. Приложение действительно работает, контент уникален, метаданные в магазине честные.
5. Файл `app-ads.txt` опубликован на сайте разработчика (см. раздел 5).

### Модерация приложения: как проходит и как повторно отправить

- Пока приложение не прошло модерацию, показы идут в **тестовом режиме** — дохода нет.
- Срок модерации — обычно **до двух суток** (иногда больше).
- Результат приходит в уведомления; при успехе статус становится **Active**.
- При отказе: исправить причину → **Реклама в приложениях → Приложения → Просмотр → Actions → Отправить на модерацию**.
  Кнопка доступна **через сутки** после отказа (при некоторых типах нарушений — через 30 дней).
- Регулярная перепроверка: даже работающие приложения перепроверяются, при серьёзных нарушениях
  аккаунт может быть приостановлен.

### Если у вас отняли трафик без предупреждения

Частые причины (по опыту и по официальным отказам):

1. Огромная доля случайных кликов — проверьте расстояние между игровыми кнопками и баннером.
2. Полноэкранная реклама слишком часто / сразу после запуска.
3. Приложение с очень низким качеством трафика (VPN-гео, фермы устройств, эмуляторы).
4. Резкий рост показов без роста активной аудитории.

## 2. Приватность: GDPR, COPPA, рекламный идентификатор

Порядок обязателен: **сначала настройки приватности, потом инициализация SDK**.

```kotlin
// до YandexAds.initialize()
YandexAds.setUserConsent(userConsent)          // согласие на использование данных для рекламы
YandexAds.setLocationTracking(false)           // геолокацию не передаём
YandexAds.setAgeRestricted(isChild)           // COPPA: ребёнок
```

Что это даёт:

- `setUserConsent(false)` — показы не персонализируются по идентификатору; eCPM обычно ниже,
  но приложение остаётся бесплатным, а правила ЕС — соблюдёнными.
- `setAgeRestricted(true)` — для приложений, адресованных детям; альтернатива — метка в манифесте:

```xml
<meta-data android:name="@string/yandex_mobileads_age_restricted_user" android:value="true" />
```

- **Рекламный идентификатор (`AD_ID`)**: с версии SDK 4.5.0 разрешение добавляется автоматически.
  Если политики (например, Google Families Policy) запрещают его использование — удалите разрешение
  из манифеста: `<uses-permission android:name="com.google.android.gms.permission.AD_ID" tools:node="remove"/>`.
  Отсутствие идентификатора снижает релевантность рекламы и доход.

В нашем проекте:

- диалог согласия показывается при первом запуске (`ui/AppRoot.kt`), SDK инициализируется только
  после выбора (`Ads.init` → `ConsentManager.applyToSdk()`);
- выбор можно изменить в настройках: «Персонализированная реклама» (там же — ссылка на политику);
- автоинициализация SDK отключена в манифесте, чтобы SDK не стартовал до согласия:

```xml
<meta-data android:name="com.yandex.mobile.ads.AUTOMATIC_SDK_INITIALIZATION" android:value="false" />
```

> Юридическая ремарка: это техническая реализация. Если вы работаете с аудиторией ЕС и
> используете сторонние сети/аналитику, подключите сертифицированный CMP (например,
> Google User Messaging Platform) и передавайте результат в `setUserConsent`. Для трафика
> РФ/СНГ описанной схемы обычно достаточно.

## 3. Google Play: обязательные требования

1. **targetSdk.** С 31 августа 2026 новые приложения и обновления должны целиться в
   **Android 16 (API 36)**. В проекте `app.targetSdk=36`; помните про ежегодный цикл.
2. **Политика конфиденциальности**. Нужна публичная ссылка; в проекте — `privacy-policy.html`
   (публикуется через GitHub Pages-репозиторий `kirillpetrov08.github.io`, ссылка прописана в `Config.PRIVACY_POLICY_URL`).
3. **Data safety** — форма, где вы декларируете, какие данные собираете. Для игры с РСЯ:
   - «Рекламный идентификатор» / «Идентификаторы устройства» — да (сбор, для рекламы);
   - «Действия в приложении» (статистика игры) — только если вы её отправляете (мы храним локально → нет);
   - «Приблизительное местоположение» — нет;
   - Данные шифруются при передаче — да; удаление по запросу — да (реализуйте почту поддержки).
4. **App content**: «Содержит рекламу» — да; рейтинг контента; целевая аудитория; категория.
5. **Разрешения**: просите минимум. У нас — `INTERNET` и `ACCESS_NETWORK_STATE`, всё для рекламы.
6. **Отсутствие запрещённого контента и политик-нарушений** (детская аудитория, финансовые обещания и т.д.).
7. **Тестирование**: новые личные аккаунты разработчиков обязаны прогнать closed-тест
   с 12 тестировщиками в течение 14 дней до продакшена (см. [10](10-google-play-release.md)).

## 4. Юридические требования РФ («О рекламе»)

- Реклама обязана маркироваться; Яндексу это делается автоматически (данные передаются в ЕРИР),
  менять метки нельзя.
- Возрастная метка и предупреждения должны занимать требуемую площадь и быть читаемыми.
- В `app-ads.txt` нельзя указывать компании, с которыми вы не работаете.

## 5. app-ads.txt: зачем, как и где

Файл `app-ads.txt` в **корне сайта разработчика** (того, что указан в Google Play) подтверждает,
какие рекламные сети авторизованы продавать инвентарь в вашем приложении.

Почему это деньги: часть DSP-проверяет файл и **не покупает показы, если его нет** — вы теряете
конкурентные ставки. Также файл используется РСЯ как способ подтвердить доступ к приложению.

Пошагово:

1. В Google Play укажите **сайт разработчика** (тот, где будет лежать файл).
2. В интерфейсе РСЯ: **Настройки → Общие → кнопка app-ads.txt** — скачайте индивидуальный фрагмент.
3. Файл должен открываться по адресу `https://ваш-сайт/app-ads.txt` (корень домена!).
4. Строки из скачанного фрагмента вставляйте **как есть**. Не сочиняйте их по памяти:
   формат `example.com, 1234, DIRECT` — это «домен рекламной системы, ID партнёра, тип отношений»,
   и **первое поле — домен рекламной системы** (у Яндекса обычно `yandex.com`), а не адрес вашего
   сайта. Встречаются варианты `yandex.com` и `ssaaq.yandex.ru` — правильный тот, что во фрагменте.
5. Обновляйте файл: партнёры меняются. РСЯ проверяет файл **раз в сутки**.

Статусы в интерфейсе РСЯ и что делать:

| Статус | Причина | Решение |
| --- | --- | --- |
| Нет данных о файле, сайт разработчика не найден | в магазине не указан сайт или он недоступен | укажите реальный сайт разработчика в Google Play |
| Файл app-ads.txt не найден на сайте | файл не в корне или отдаёт 404 | положите файл в корень домена |
| Файл app-ads.txt устарел | не хватает строк от партнёров | добавьте строки из РСЯ и **Отправить на проверку** |

Готовый шаблон лежит в корне репозитория: `app-ads.txt` (внутри — инструкция; активные строки
появляются после подстановки фрагмента из РСЯ).

## 6. Быстрая самопроверка перед отправкой на модерацию

- [ ] Баннер не перекрывает контент и не вплотную к кнопкам; при появлении ничего не «прыгает».
- [ ] Полноэкранная реклама — только в паузах, не чаще политики, не в первый момент.
- [ ] Rewarded — только по кнопке, награда выдаётся по `onRewarded`.
- [ ] Нет ни одного «стимула кликнуть» и ни одного своего элемента поверх креатива.
- [ ] Согласие на данные спрашивается до инициализации SDK.
- [ ] app-ads.txt опубликован и открывается в браузере.
- [ ] Реальные ID блоков подставлены, `ads.testMode=false`.
- [ ] Политика конфиденциальности опубликована и указана в Google Play.
