# Межстраничная реклама (Interstitial)

## Что это

Полноэкранное объявление, которое закрывает приложение целиком. Пользователь может либо перейти
по объявлению, либо закрыть его и вернуться в приложение. Используется **в естественных паузах**:
конец партии, переход на следующий уровень, завершение загрузки/сохранения.

Из-за полного захвата внимания стоимость показа выше, чем у баннера — и одновременно это самый
опасный формат для удержания: слишком частые показы убивают retention, а значит и доход.

## Интеграция (SDK 8.x)

```kotlin
// Один загрузчик на приложение/экран — так рекомендует Яндекс
private val loader = InterstitialAdLoader(context)

fun preload() {
    loader.loadAd(
        AdRequest.Builder(adUnitId).build(),
        object : InterstitialAdLoadListener {
            override fun onAdLoaded(ad: InterstitialAd) { interstitial = ad }
            override fun onAdFailedToLoad(error: AdRequestError) { /* см. про backoff ниже */ }
        },
    )
}

fun show(activity: Activity) {
    interstitial?.apply {
        setAdEventListener(object : InterstitialAdEventListener {
            override fun onAdShown() {}
            override fun onAdFailedToShow(adError: AdError) { /* очистить и перезагрузить */ }
            override fun onAdDismissed() { /* очистить ссылку и перезагрузить */ }
            override fun onAdClicked() {}
            override fun onAdImpression(data: ImpressionData?) {}
        })
        show(activity)
    }
}
```

## Особенности, обязательные по документации

1. **Все вызовы SDK — из главного потока.**
2. **Не перезагружать объявление из `onAdFailedToLoad`** — иначе бесконечный цикл неудачных запросов.
   У нас реализован backoff: повтор через 30 секунд, не чаще (`InterstitialAdController`).
3. **Держать сильные ссылки** на загрузчик и объявление, пока экран живёт — иначе сборщик мусора
   уберёт объекты и показ не состоится.
4. **Один инстанс `InterstitialAdLoader`** на все загрузки.
5. После показа/ошибки — `setAdEventListener(null)` и обнулить ссылку на объявление (иначе утечка).
6. Показывать только в паузах: между уровнями, после окончания партии, после целевого действия.

## Частотная политика в нашей игре

`app/src/main/java/com/blockpuzzle/app/ads/AdPolicy.kt`:

- интервал между показами — не менее **60 секунд** (`ads.interstitialIntervalSeconds`);
- показ не чаще, чем **каждый второй проигрыш** (`ads.interstitialGamesInterval=2`);
- показ только при старте новой партии после проигрыша — то есть после того, как пользователь
  сам нажал «Играть снова» (естественная пауза, ожидание загрузки игрового поля).

Значения меняются без правки кода — в `gradle.properties`. Логика покрыта unit-тестами
(`AdPolicyTest`), потому что «случайно сломанная» частотка — прямой путь к падению метрик и
к жалобам модерации.

## Рекомендации по частоте (эмпирика по играм)

| Тип игры | Интервал | Комментарий |
| --- | --- | --- |
| Гиперказуальная 1–2 мин на сессию | 60–90 сек, каждый 2–3-й проигрыш | чаще — теряете игроков |
| Казуальная с уровнями | каждые 2–3 уровня + 60 сек | классика |
| Если игрок в топе по времени | 120+ сек | активные игроки самые ценные |

Практический тест: поднимите частоту, посмотрите Retention D1/D7 в Google Play Console
(или AppMetrica). Если D1 падает больше чем на 3–5 пунктов — возвращайте прежнюю частоту.

## Ошибки и нюансы

- Если `onAdFailedToShow` — не начисляйте ничего пользователю и перезагрузите объявление.
- Не показывайте interstitial, если пользователь только что закрыл другой полноэкранный формат
  (rewarded/interstitial): ждите 30–60 секунд.
- Не показывайте interstitial на первом запуске сразу после App Open.
- В логах SDK есть отдельный статус проверки формата:
  `[Integration] Ad type interstitial was integrated successfully`.
