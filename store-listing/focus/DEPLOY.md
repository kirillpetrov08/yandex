# Публикация приложения «Фокус» — пошагово

Это отдельное приложение от «Блоки»: **package name `com.ayaks.focus`**, модуль `:mind`. Пользовательские настройки, история и объявления в него не импортируются. Выполняйте шаги по порядку; для загрузки в магазины понадобятся собственная учётная запись разработчика и ключ подписи. Ключи и их пароли нельзя присылать в чат или добавлять в Git.

## Перед релизом: одна настройка рекламы

1. Войдите в кабинет Яндекс Рекламы и создайте **отдельное Android-приложение** с package name `com.ayaks.focus`.
2. Создайте **один адаптивный баннер**. Больше форматов в текущей версии нет.
3. Скопируйте точный ID блока из кабинета. Внесите его в `gradle.properties`:

   ```properties
   focus.bannerUnitId=R-M-ваш-фактический-ID
   ```

   Не используйте ID от другой игры, demo-ID или пример. Пустое значение оставляет игру полностью работоспособной без рекламы, но финальный релиз тогда не содержит баннер.
4. Проверьте `site/app-ads.txt` по строке, сформированной в кабинете Яндекс Рекламы. Не меняйте идентификатор издателя и не угадывайте строку.

Реклама должна загружаться только на главной, выборе режима, результате, статистике и настройках. Во время игрового раунда баннера нет. Геолокация для SDK отключена; приложение просит выбрать режим рекламы до инициализации SDK.

## Собрать и проверить приложения

### Самый простой путь — GitHub Actions

1. Добавьте изменения ветки `arena/dc0a599c-yandex` в свой GitHub-репозиторий обычным способом. Не переключайтесь на другую ветку; workflow запускается на ветках `arena/**`.
2. Откройте репозиторий на GitHub → **Actions** → **Android CI** → последний запуск для этой ветки.
3. Дождитесь зелёного workflow. Он должен завершить тесты, `:mind:assembleDebug`, `:mind:assembleRelease` и `:mind:bundleRelease`. Если шаг красный — **не загружайте сборку в магазин**; сохраните полный log и устраните ошибку.
4. Внизу успешного запуска скачайте artifact `build-outputs`. Ищите файлы под `mind/build/outputs/`:
   - `bundle/release/mind-release.aab` или `bundle/release/*.aab` — Google Play;
   - `apk/release/*.apk` — ручная установка и тест;
   - `apk/debug/*.apk` — только для внутренней проверки.
5. Установите release APK на реальный Android-телефон. Проверьте запуск, каждый режим, выход/возврат, счёт и настройки; попробуйте включить/выключить звук, вибрацию и персонализацию. Если указан production ID — убедитесь, что баннер есть на неигровых экранах и отсутствует в раундах. **Не нажимайте собственные объявления.**
6. Проверьте подпись: без upload-key workflow использует debug-подпись — такой AAB не подходит для Play. Храните upload-key и пароль в менеджере паролей и двух защищённых резервных местах. Для CI создайте секреты GitHub `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD` по общему гайду [`../../DEPLOY.md`](../../DEPLOY.md). Не присылайте ключи агенту.

### Локальная сборка (если установлен Android Studio/JDK 17)

Из корня репозитория:

```bash
./gradlew :mind:testDebugUnitTest :mind:assembleDebug
./gradlew :mind:assembleRelease :mind:bundleRelease
```

Если команда сообщает, что не найдена Java, установите Android Studio с JDK 17 или используйте GitHub Actions.

## Опубликовать политику конфиденциальности

1. В публичный сайт разработчика (GitHub Pages `kirillpetrov08.github.io`) скопируйте **содержимое** `site/`: обновлённый `index.html` и `focus-privacy-policy.html`.
2. Откройте адрес `https://kirillpetrov08.github.io/focus-privacy-policy.html` в приватном окне и проверьте, что страница открывается без входа в GitHub.
3. Сохраните этот точный URL для карточек магазинов. Если для сайта используется другой домен, замените URL также в карточке, приложении и настройках магазина перед релизом.
4. Сверьте опубликованный `app-ads.txt` с актуальным фрагментом из Яндекс Рекламы. Для сайта ранее согласована строка `yandex.com, 110347355, DIRECT`; всё равно сверяйте с действующим кабинетом.

## Google Play Console

1. Создайте **новое приложение** с package name `com.ayaks.focus`, тип «Игра», распространение бесплатное. Не создавайте карточку под `com.blockpuzzle.app`.
2. В Store listing перенесите материалы из [`ru.md`](ru.md), feature graphic [`feature-graphic-1024x500.png`](feature-graphic-1024x500.png), иконку [`../../mind/store/icon-512.png`](../../mind/store/icon-512.png) и скриншоты из [`screenshots/`](screenshots/).
3. Укажите поддержку `kirillpetrov08@gmail.com`, разработчика `Ayaks`, сайт и опубликованную политику.
4. Заполните Ads, content rating, Target audience и Data Safety по текущим формам Play Console. `data-safety.md` — помощь для ответов, не автоматическая декларация: сверяйте объединённый manifest и SDK disclosure до отправки. Приложение не должно рекламироваться как медицинская диагностика или лечение.
5. Создайте внутренний тест, загрузите подписанный `:mind` AAB, добавьте тестировщиков, проверьте install flow. Для новых личных аккаунтов выполните показанное Play Console обязательное закрытое тестирование перед запросом доступа к production.
6. После проверок отправьте релиз на review. Не используйте автоматическую загрузку workflow: текущий job публикации по умолчанию привязан к `com.blockpuzzle.app`.

## RuStore

1. Создайте отдельную карточку приложения и загрузите подписанный **APK** по требованиям актуального кабинета RuStore (сверьте максимальный размер, подпись и целевые API перед отправкой).
2. Возьмите русское имя, короткое и полное описание из [`ru.md`](ru.md); загрузите иконку 512×512, скриншоты и опубликованную политику.
3. Заполните возрастную и рекламную декларации по анкете RuStore. Не копируйте рейтинг Google Play без проверки.
4. Отправьте на модерацию; после публикации установите приложение через магазин и ещё раз проверьте запуск и доступность ссылки политики.
